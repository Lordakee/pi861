## 0. 范围与产品边界（继承任务书"角色、目标与工作边界"）

- Pi861 是用户自研 Agent 平台，复用 Pi 的模型适配、工具循环、会话与扩展接口；不把 Codex、Claude Code 等其他 Agent 产品接入为执行插件。
- 开发仅在 `feat/pi861-runtime-v1` 及其任务分支进行；不合并 main、不 force push、不发布包、不启动用户业务任务。
- 未获授权不得运行付费模型验收或使用真实业务数据库、MCP 账户与生产数据。
- 不删除已有功能、不降低验收要求、不移除失败检查来让 CI 变绿。
- 历史文档（VERIFICATION.md）仅作历史证据，不作为当前 HEAD 的通过证明。

## 1. 通用横切需求（G）

适用于 R1–R8 所有模块，来源于任务书与开发计划的共性约束。

| 编号 | 需求（含默认值与行为） |
| --- | --- |
| G1 | 身份与授权只能由可信宿主或服务端产生：tenant/principal/scope、Role 与 grants 来自配置文件或宿主上下文，模型输出中的 tenant、role、scope 字段不授予任何权限。默认 principal：`tenantId=local`、`principalId=PI861_AGENT_ID ?? main`。 |
| G2 | 所有持久写入具备 requestId 幂等与回执：同一 requestId 重放返回同一回执；重放意图变化（hash 不一致）显式冲突报错，不默默覆盖。适用于记忆写入、协调者变更、MCP 操作日志。 |
| G3 | 版本与冲突显式：记忆写入带 expectedRevision（CAS）；原始 Skill 与发布版本不可变（digest 对比）；计划追加带 expectedVersion；接口/事件/持久数据有版本号，冲突显式返回。 |
| G4 | 生命周期与副作用分离：取消等待不等于外部操作未发生。未知结果（unknown）必须进入核对流程，禁止定时重放或盲目重试；已确认成功的工具结果保留，不因重试重复执行。 |
| G5 | 存储锁内禁止外部调用：数据库/文件状态锁的事务回调内不得调用模型或远程工具；提炼的模型调用在领取事务之外执行，提交时重新校验版本、撤回状态与租约。 |
| G6 | 集成不得用 `any`、`ts-ignore`、双重断言、排除目录或关闭检查来掩盖不兼容；现有窄端口适配必须有实际类型与宿主契约测试。（当前 runtime.ts 存在双重断言，属 P0 修复范围。） |
| G7 | 测试分级诚实：确定性测试不得隐式触发付费 API；fixture/模拟宿主证明协议与安全行为，真实模型/真实搜索/真实多节点验收单独、默认关闭、需明确授权；未跑与 skip 不计通过。 |
| G8 | 配置不包含真实密钥：数据库与远程 Worker 凭据在配置中只存环境变量名（`database.urlEnv`、`remoteWorkers[].tokenEnv`），运行时从环境读取；密钥不进入模型上下文与日志。 |

## 2. R1 多模型执行策略

来源：IMPLEMENTATION_PLAN R1 + 任务书第 4 节。

| 编号 | 需求（含默认值与行为） |
| --- | --- |
| R1.1 | 每个 Agent 拥有多个完整模型配置：稳定配置身份（id/revision）、provider/model、能力清单（capabilities）、上下文窗口（contextWindow）、成本（costRank）、启用开关，以及账户/端点故障域、计费参数与数据出站边界；子 Agent 使用同一策略体系。 |
| R1.2 | 默认接待模型一次决策初始模型与执行模式：`direct`（直接完成，不为形式再启动第二个路由 Agent）/ `fixed`（固定模型）/ `dynamic`（动态路由）。决策输入包含任务文本与候选模型清单，输出必须选择合格目标并给出 minQuality 下限与理由。 |
| R1.3 | 固定模式正常执行不反复重新选择，但保留异常升级通道（capability_gap、连续验证失败升级）；动态模式仅在阶段、需求或证据变化事件时重评估，不逐 token/逐工具调用路由模型。 |
| R1.4 | 复杂分析与规划质量优先；批量可验证工作可选低价模型；能力不按价格简单等同。能力不足、未授权（allowlist）、上下文容量不够的配置是硬过滤，不得被选择。 |
| R1.5 | 路由输入包含当前阶段、reason、验证结果、无进展证据与范围变化；路由器必须获得阶段与证据摘要，不能只反复分类最初一句用户输入；不能仅靠廉价模型自述有信心。 |
| R1.6 | 升级可以及时；降级需要明确的阶段完成与质量条件；不在不安全边界（有未决工具操作时）来回切换。 |
| R1.7 | `failoverEnabled`、`failbackEnabled` 为独立开关，四种组合语义完整：关 failover 不自动切入备用、不强制赶回已处于备用状态的执行；关 failback 不自动回切、不为该任务进行仅服务回切的探测。支持运行中修改（`/model-policy failover|failback on|off`），修改不重做已完成操作。全局默认、Agent 覆盖、子 Agent 继承行为需有文档与测试。 |
| R1.8 | 接待分类器、规划器、记忆提炼、Skill 编译等辅助模型调用与主执行共用可靠性与预算机制：纳入请求计量与全局预算，不得裸连。 |
| R1.9 | 计量覆盖所有实际请求尝试、输入/输出/缓存用量、费用与探测/辅助调用；未知用量明确标记未知，不得写成零；统一预算不能仅限"自动继续次数"。 |

## 3. R2 模型故障接管与恢复回切

来源：IMPLEMENTATION_PLAN R2 + 任务书第 4 节。

| 编号 | 需求（含默认值与行为） |
| --- | --- |
| R2.1 | preferred（当前首选）与 active（实际执行）配置分离；故障切换只改 active，不改变 preferred。 |
| R2.2 | 备用接管与自动回切是两个独立开关（见 R1.7）；关闭 failback 后清除未决探测；运行中修改立即生效于下一次决策。 |
| R2.3 | 故障分类（transient/rate-limit/auth/quota/invalid/context/cancelled）；连接、请求与总截止时间；有限重试次数；指数退避（封顶 maxProbeIntervalMs）；尊重 Retry-After；连续 N 次探测成功（requiredProbeSuccesses）才确认稳定；回切只发生在安全边界（无未决操作）。用户取消与服务拒绝不当作需要换模型绕过的瞬态错误。 |
| R2.4 | 用户取消不触发接管；迟到旧响应没有执行权（generation/attempt 归属校验）；已确认工具结果保留；未知副作用先核对，不盲目重试。 |
| R2.5 | 只有合格且获准的备用才切换；没有合格备用时保存进度（checkpoint 持久化）并暂停/报错，不静默降级。 |
| R2.6 | 健康状态在合适的配置/账户/故障域内共享；探测单飞（同一时刻至多一个探测）；探测有预算上限；有背压，防止多个子 Agent 同时压垮恢复中的服务；关闭 failback 后停止仅服务于回切的探测。 |
| R2.7 | 复核并消除绕过路径：direct/generator 辅助调用与只读 Pi plannerSession 不得绕过故障机制或全局预算。 |
| R2.8 | `pi861_model_route` 工具提交的 reason 与新证据必须真正进入后续路由判断（阶段、验证结果、无进展证据、范围变化），不得只传 signal 丢弃 reason。 |
| R2.9 | 新任务、会话切换、暂停/恢复后首选模型与探测开关保持正确；checkpoint 恢复校验策略指纹（policyHash），恢复后 generation+1，旧请求不获执行权。 |
| R2.10 | 流式中断不能把半截工具参数执行出去；新旧尝试有执行权与迟到响应保护；当前缓冲式 wrapper 属于已知限制，需演进为增量流式并明确设计取消与工具语义（工具参数完整且验证通过后才可派发）。 |

## 4. R3 持续多 Agent / 多模块 / 多节点

来源：IMPLEMENTATION_PLAN R3 + 任务书第 7 节。

| 编号 | 需求（含默认值与行为） |
| --- | --- |
| R3.1 | 目标、计划、任务、执行尝试、产物与验收结果分开建模；小组与队列持续存在，执行 Agent 可更换。默认约束：maxConcurrent=2、每任务 maxAttempts=2、项目 maxTasks=100（均为配置可覆盖）。 |
| R3.2 | 事件驱动的就绪队列持续补位：每个独立验证通过的结果立即解锁依赖，不等待整批最慢任务；队列按优先级与 id 排序补位。 |
| R3.3 | 空闲后唤醒：任务结束、验收、依赖解除、计划追加、节点恢复和人工解除阻塞都能重新派工；Runner 不得在无运行任务时永久退出。 |
| R3.4 | 前置依赖（dependsOn 全 done）、写入范围（writeScopes 冲突互斥）、节点能力（capabilities/role/model 匹配）、租约（token+attempt+过期）与尝试编号共同约束执行；依赖环拒绝；租约过期后旧结果拒绝提交。 |
| R3.5 | 计划滚动更新：接入有授权和预算的滚动规划入口、低水位补充、任务调整、依赖环检查与计划版本冲突检测（expectedVersion CAS）。 |
| R3.6 | 全任务树统一容量与预算：规划、执行、审核、返工、集成与远程 Worker 均纳入计量；等待父任务可释放执行名额，但后代仍受总量约束。 |
| R3.7 | 多节点运输：远程节点采用独立检出，跨节点通过版本化任务协议与校验产物（git bundle + sha256）传递，不共享可写工作目录；远程请求重新验证完整差异而非只信声称输出。 |
| R3.8 | 隔离后端：Shell 或测试命令开启时按已选隔离后端限制凭据、网络、进程与宿主文件；worktree/文件钩子不等于 OS 沙箱；暂未提供的保护必须标明。 |
| R3.9 | 集成队列单一有效执行权：防止重复 `/goal resume` 或另一协调进程同时向同一集成工作区合并；租约交接前确认旧 Git 进程已收敛。 |
| R3.10 | 集成/测试失败保留现场（workspace 与证据保留）并提供可追踪修复路径；故障限制在对应集成流程，不永久锁死其他安全任务，也不跳过失败强行继续。 |
| R3.11 | 任务与工作区身份包含 goal/run/task/attempt 维度，避免下一目标复用 taskId 时与旧分支/路径碰撞。 |
| R3.12 | 取消、暂停与恢复语义分别确定；运行中旧请求与远程迟到结果不能覆盖当前状态；节点故障时安全任务从检查点恢复，未知副作用进入核对。 |
| R3.13 | RemoteWorker 提供可启动、可配置、受认证（强 bearer token）、具备心跳/租约、容量通告、取消与收敛关闭的部署入口；所有身份与能力由可信配置约束，不信任请求自报；重启后未决任务标记 unknown 待核对。 |

## 5. R4 Skill 加工与治理

来源：IMPLEMENTATION_PLAN R4 + 任务书第 5 节 Skill 部分。

| 编号 | 需求（含默认值与行为） |
| --- | --- |
| R4.1 | 原始包归档全部必要正文、脚本与资源（逐文件 base64+sha256），来源版本不可变；原始 Skill 不进入默认上下文与自动推荐，但保留显式调用；隐藏不是安全隔离。默认限制：单文件 2 MiB、至多 1000 文件、总量 16 MiB、必须含 SKILL.md。 |
| R4.2 | 全文理解后生成运行版：读全部文档而非描述片段；重复流程实质去重；必要差异表达为互斥分支（conflictsWith）或兼容补充模块；保留安全约束、必要参数、失败处理与验证，不得发明工具或放宽权限。 |
| R4.3 | 安装或更新时按全文自动判断能力归属（chooseSkillGroup），自动找出相关已安装 Skill；人工指定分组保留为覆盖选项，不能成为唯一方式。 |
| R4.4 | 浅目录与搜索共用同一份结构化能力记录；选中后加载完整必要约束（instructions+分支约束），不是只加载若干相似片段执行。 |
| R4.5 | 编译候选、验证、发布分别执行并分别记录；来源与权限冲突不自动合并；发布版本不可变且固定到运行中任务（更新不替换运行中版本）。 |
| R4.6 | 编译输入必须包含真实、已批准的工具绑定；不得提示模型"从输入使用绑定"却不传入绑定。 |
| R4.7 | 资源路径使用稳定标识和版本清单；处理符号链接（拒绝）、路径穿越（拒绝）、二进制资源（base64 归档）、超大包（限额）与 Windows 空格路径（配置注入而非命令行分词）。 |
| R4.8 | 安装阶段不执行来源脚本（安装路径无脚本执行点，属设计约束）。 |
| R4.9 | 结构验证、行为测试、人工审核与人工接受是不同证据类型，发布证据必须能区分；用户点击确认不等于行为测试，不得始终返回 `passed:true` 后称为自动验收。 |
| R4.10 | 支持更新、卸载、受影响重建、回滚（rollback）与运行中版本固定。 |

## 6. R5 岗位授权与 MCP 懒加载

来源：IMPLEMENTATION_PLAN R5 + 任务书第 5 节 MCP 部分。

| 编号 | 需求（含默认值与行为） |
| --- | --- |
| R5.1 | 岗位限定 MCP 服务、工具操作、账户、资源与数据出站范围：Role.grants 精确到 toolId+accountId+resourceIds；ResourceRule 以 equals 参数约束或 operator 断言 endpointConfined；分类（readOnly 等）来自可信配置，不来自服务器注解。 |
| R5.2 | 每个开放 MCP 有已发布 Skill 入口覆盖（不强制一对一）：`/mcp refresh` 发现元数据并发布确定性资源绑定 Skill；只有授权分支出现在角色视图，工具在 Skill 激活前保持非激活。 |
| R5.3 | Skill 激活按分支/阶段解析结构化依赖，只加载该分支/阶段所需工具，不整包注入；未激活的能力工具按名直调被拦截。 |
| R5.4 | 发现不授予权限；激活、恢复和每次实际调用都重新验证权限与参数；接口（schemaHash）变更使旧绑定失效，必须重新激活。 |
| R5.5 | 工具身份包含服务、账户、资源与 schema 版本；同名工具、多账户、同一工具供多个 Skill 使用时不得互相覆盖注册闭包或借用另一 Skill 的授权。 |
| R5.6 | MCP 客户端覆盖握手（协议版本协商）、工具分页、通知、schema 变更检测、取消、重连（404 会话失效）、大小限制与有界超时；优先采用经过核查的官方 SDK/协议实现；SSE 提前结束视为 unknown，不重放工具操作。 |
| R5.7 | 主动浏览不能触发业务写入；模型不能按隐藏工具名绕过门禁；撤权即时作用于调用与结果读取（currentRole 每次取当前值）。 |
| R5.8 | 大结果保存受控引用（resultRef）并支持分页读取与完整性标记；引用权限与原调用保持关联，撤权后不可读。 |
| R5.9 | 副作用使用持久操作回执：at-most-once 派发、等价未决操作阻塞自动重发、unknown 需可信核对（operator resolve）后才能新建等价意图；结果与回执大小有界。 |
| R5.10 | 通用脚本、Shell、任意扩展不能成为绕过岗位权限的后门；Worker 模式默认禁用 Shell（allowWorkerShell 显式开启）并收敛基础工具集。 |
| R5.11 | 可信本地模式与生产隔离模式明确区分；原始 Skill、Shell、脚本和额外扩展均受相同岗位边界约束。 |
| R5.12 | 数据出站边界：搜索/网页读取每次重新验证权限与出站策略；外部内容保持不可信数据属性（详见 R7）。 |

## 7. R6 多层记忆与 PostgreSQL

来源：IMPLEMENTATION_PLAN R6 + 任务书第 6 节。

| 编号 | 需求（含默认值与行为） |
| --- | --- |
| R6.1 | 三个独立维度：用途（constraint/working/project/experience/evidence）、访问范围（scope）、读取深度（L0 摘要/L1 概览/L2 详情）；短记录不必机械产生三份；摘要必须关联源版本（sourceRevision）。 |
| R6.2 | 范围不自动继承、扩大：readScopes/writeScopes 显式授权；writeScopes ⊆ readScopes；未授权范围查询返回空而非报错泄漏。 |
| R6.3 | 自动读取装配：启动任务、接手、换模型、压缩后、换节点时直接装配必要状态与固定约束（不依赖关键词"碰巧"命中安全约束）。 |
| R6.4 | 长期经验按任务/事件召回；简单任务不强制深度检索；召回去重、有字节预算（默认 maxContextBytes=6000）、增量变化（delta 游标）与撤回失效。 |
| R6.5 | 用户输入自动采集为候选（candidate）记录：来源限 interactive/rpc；启发式敏感检测拒绝凭据；超长截断并标注；召回不回显刚捕获的输入。默认开启（`PI861_AUTO_CAPTURE=0` 关闭）。 |
| R6.6 | 工具执行结果自动采集：`tool_execution_end` 及时保存（不等会话结束）；排除 pi861 自身工具；大小与敏感过滤。默认开启（config `memory.autoCapture=false` 关闭）。 |
| R6.7 | 超大或敏感工具结果不静默消失：保存受控引用和必要状态，不把秘密写入摘要。 |
| R6.8 | 提炼治理：持久任务（queued/running/done/obsolete/failed）、领取租约（token+expiresAt）、有界尝试（默认 attempts<3）、提交时版本/撤回/租约重校验；模型调用在存储锁外执行；派生视图发布也产生变更事件。 |
| R6.9 | 提炼失败分类、重试与人工处理路径：一次暂时失败不得永久丢掉整理工作（当前 failed 任务不再被领取属已知缺口，必须修复）。 |
| R6.10 | 事实来源区分用户表达（user）、工具观察（tool）、模型假设（inference）与召回（recall）；recall 不得作为新证据；inference 不得自确认或成为 constraint；facts 必须带原文字面引用（quote 校验）。 |
| R6.11 | 撤回语义：tombstone（内容指纹+来源指纹）阻止同文本/同来源再写入；传播到摘要（projection 删除）、待运行任务（obsolete）与 outbox 事件；撤回不等于物理擦除。 |
| R6.12 | 子组分支实现不自动升格为项目已采用事实（仅集成验收事件可发布）；经验可生成 Skill 候选但必须走 R4 验证发布流程。 |
| R6.13 | PostgreSQL 权威存储：正文、事实、来源、版本、回执、访问控制与可重建索引（outbox）同一事务提交；参数化查询、并发版本检查（FOR UPDATE+advisory lock）、requestId 重放、事务 outbox；未知 COMMIT 结果保持 requestId 可重试。 |
| R6.14 | 外部连接配置：显式连接串（环境变量注入）、TLS 默认强制（rejectUnauthorized）、CA 文件、连接池上限与超时；迁移权限与运行账号分离（非超级用户、非 BYPASSRLS）；备份与恢复为运维要求。 |
| R6.15 | 数据模型统一：PostgresStateStore（项目级 JSON 状态读改写）与 PostgresMemory（逐记录 SQL 模型）不得静默分叉；必须选定权威模型并提供显式迁移。 |
| R6.16 | 检索：关键词基线（含中文分词）；pgvector 为可配置增强，未实现时必须明确标注（不得装饰性开关）；中文、代码符号与文件路径检索测试；向量模型/维度/版本绑定与迁移策略（实现时）。 |
| R6.17 | 数据库不可用时不生成第二份共享真相：外部 backend 失败报错、不悄悄切换本地权威；本地待同步记录明确未提交（当前为失败丢弃+警告，待改造成待同步队列）；关键检查点未可靠提交则暂停对应执行边界。 |
| R6.18 | 自动召回、自动采集、自动提炼与主动工具分别可控（环境变量/配置/命令三层开关）；与项目/岗位设置形成清晰继承规则（继承层级当前未实现）。 |

## 9. R8 /goal

来源：IMPLEMENTATION_PLAN R8 + 任务书第 7 节 /goal 部分。

| 编号 | 需求（含默认值与行为） |
| --- | --- |
| R8.1 | `/goal` 支持创建、状态（status）、修改（edit，需先暂停）、暂停（pause）、恢复（resume）、预算（budget，只升不重置已用次数）、接受（accept，仅 review 状态且有证据）与清除（clear）。完整 runtime 入口需提供同等动词集合。 |
| R8.2 | 目标包含验收条件、进度与证据：模型经 `pi861_goal_report` 提交 runToken+进度+证据；无证据不得申请完成；提交完成只进入 review，人工接受是独立步骤。 |
| R8.3 | 自动续跑有明确上限（默认 maxRuns=20；usedRuns 单调递增）；连续两次无有效进度报告暂停；用户输入、中止、报错不自动重放；暂停期间不派发。 |
| R8.4 | 接入统一调度：完整 runtime 的 `/goal` 驱动 ProjectCoordinator 队列（managedGoal 抑制旧基础入口防双注册），不叠加另一套不受计量的无限 sendUserMessage 循环；基础入口的续跑为单飞 setTimeout 续跑（同一时刻至多一个）。 |
| R8.5 | 会话恢复是被动式：恢复的 active 目标降级为 paused，要求显式 resume；恢复清除 runToken/report；无效恢复状态拒绝自动执行。 |
| R8.6 | 完整 runtime `/goal` 创建链路：只读 Pi planner 会话检查仓库 → 有界项目计划（仅允许配置内 modelIds/roleIds/checkIds）→ coordinator 创建 → Worker 池执行 → 检查 → 受控集成 → 验收。 |
| R8.7 | 可见状态解释未满并发的具体原因（依赖、预算、资源、审核、权限、故障或没有合格工作），不只显示在线 Agent 数。 |
| R8.8 | 不靠大模型自报 done：完成由目标合同（自动检查证据+独立审核或用户接受）判定；人工接受与自动质量证明在报告中区分；重复完成事件（同 token settle）不重复计数。 |
