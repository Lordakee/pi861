## 4. R1–R2：多模型路由、故障接管、自动回切

复用并核查 routing.ts、live/model-runtime.ts、live/compilers.ts 和 runtime.ts。

必须实现：
- 每个 Agent 有多个完整模型配置，包含稳定配置身份、版本、能力、上下文限制、成本及数据出站边界；子 Agent 使用同一策略体系。
- 默认接待模型一次决策初始模型与执行模式：直接完成、固定模型、动态路由。直接完成不是为了形式又启动第二个路由 Agent。
- 固定模式正常执行不反复重新选择，但保留异常升级；动态模式在阶段、需求或证据变化时重评估，而非每个 token/工具都调用路由模型。
- 复杂分析与规划质量优先；批量可验证工作可选低价模型；模型能力不按价格简单等同。
- 运行时验证失败、无进展、能力障碍和任务范围变化要影响路由；不能仅靠廉价模型自述有信心。路由器必须获得当前阶段和证据摘要，不能只反复分类最初一句用户输入。
- 升级可以及时，降级需要明确的阶段完成和质量条件；不在不安全边界来回切换。
- preferred 与 active 分开；业务升级或用户改配置会更新当前首选，旧模型恢复不得覆盖新首选。
- failoverEnabled、failbackEnabled 是独立开关，支持四种组合；全局默认、Agent 覆盖、子 Agent 继承及运行中修改行为均有文档和测试。
- 关闭 failover 后不自动切入备用；已处于备用状态时不被强制赶回故障配置。关闭 failback 后不自动回切，不为该任务进行仅用于回切的无意义探测。
- 故障分类、连接/首响应/进展/总截止时间、有限重试、退避、Retry-After、熔断、稳定性确认与安全回切；用户取消和服务拒绝不当作需要换模型绕过的瞬态错误。
- 有合格备用才切换；没有合格且获准的数据处理配置就保存进度暂停，不静默降级。
- 流式中断不能把半截工具参数执行出去；新旧尝试有执行权与迟到响应保护；已确认工具结果保留，未知副作用先核对。
- 健康状态在合适的配置/账户/故障域内共享，探测单飞、有预算、有背压，防止多个子 Agent 同时压垮恢复中的服务。
- 接待分类器、规划器、记忆整理、Skill 编译等辅助模型调用也要受可靠性和预算机制管理，不能主执行受控而辅助调用裸连。
- 计量包括所有实际请求尝试、输入/输出/缓存用量、费用和探测/辅助调用。未知用量明确未知，不能写成零。统一预算不能仅限“自动继续次数”。

必须复核的现有路径：
- direct/generator 与只读 Pi plannerSession 是否绕过故障或全局预算。
- pi861_model_route 当前接收 reason，但是否真正把原因和新证据用于后续判断。
- 新任务、会话切换、暂停/恢复后首选模型与探测开关是否保持正确。
- 当前 wrapper 缓冲完整响应再返回，不能称为已完成流式体验；明确设计并测试中断、取消及工具语义。

- 资源路径使用稳定标识和版本清单，处理符号链接、硬链接、路径穿越、二进制资源、超大包及 Windows 空格路径。不要在安装阶段运行来源脚本。

MCP：
- 岗位限定服务、工具操作、账户、资源和数据范围；必须由可信宿主提供身份，模型不能自行扩大范围。
- 每个开放 MCP 有已发布 Skill 入口覆盖，不强制一对一。默认只保留基础控制工具，Skill 激活时按分支/阶段加载必要工具，不整包注入。
- 复用已有 stdio/HTTP 客户端，核对锁定协议和需要的能力，测试握手、工具分页、通知、变更、取消、重连、大小限制及有界超时。优先采用经过检查的官方 SDK/协议实现，避免自制解析器遗漏边界。
- 激活、恢复和每次实际调用重新验证权限及参数；接口变更必须使旧绑定失效。发现工具不能授予权限。
- 工具身份包含服务、账户、资源与版本；同名工具、多账户、同一工具供多个 Skill 使用时不能互相覆盖注册闭包或误用另一个 Skill 的授权。
- 主动浏览不能触发业务写入；模型不能按隐藏工具名绕过门禁。撤权不仅影响搜索，还要影响已激活工具和结果引用。
- 大结果保存受控引用，分页/按字段读取，并说明是否完整；权限与原调用保持关联。
- 副作用使用稳定业务操作标识、持久回执和核对机制；不是换一个 toolCallId 就可自动重发。不要宣称本地 UUID 能使任意外部系统严格只执行一次。
- 通用脚本、Shell、任意扩展不能成为绕过岗位权限的后门。可信本地模式与生产隔离模式明确区分。

## 6. R6：适合 Pi 的多层自动记忆与外接 PostgreSQL

现有 LayeredMemory 已有持久状态接口、派生摘要、提炼任务和 delta，不要退回“只存一个 MEMORY.md”；也不能把这些存在等同于完整记忆产品已验收。

必须实现三个独立维度：
1. 用途：固定约束/确认偏好、任务工作记忆、项目协作知识、长期经验、历史证据。
2. 范围：用户、项目、小组、Agent、任务，以及经批准的跨项目共享。范围不自动继承、扩大。
3. 读取深度：L0 摘要、L1 概览、L2 详情。短记录不必机械产生三份；摘要必须关联源版本。

自动读取：
- 启动任务、接手、换模型、压缩后、换节点时直接装配必要状态与固定约束。
- 长期经验按任务/事件召回，简单任务不强制深度检索；去重、预算、稳定前缀、增量变化与撤回失效。
- 不能依赖一次关键词搜索“碰巧”找到安全约束；记忆数据不作为更高优先级指令或权限。

自动写入与治理：
- 执行事件与工具回执及时保存；不等会话结束再总结。超大/敏感工具结果不应静默消失：保存安全引用和必要状态，不把秘密写入摘要。
- 提炼使用持久任务/outbox、租约、有界重试、版本校验和幂等回执；外部模型调用不占住数据库锁。
- 已有 enrich 将失败任务标为 failed，而领取条件目前只选 queued 或过期 running：补齐失败分类、重试与人工处理路径，避免一次暂时失败永久丢掉整理工作。
- 事实来源区分用户表达、工具观察、模型假设和验证结果；一次引用包含某段原文不等于推断已被原文支持。控制错误提炼和记忆污染。
- 对用户纠正、时效、适用版本、冲突、替代、撤回和删除设计明确行为。旧来源、索引、摘要、缓存及待运行任务不能复活已撤回记忆。
- 检索结果及已生成摘要不当成独立新证据；不能多 Agent 转述同一推测后就当作多份证据。
- 子组分支上完成的实现不自动升格为项目已采用的事实；以实际集成验收事件发布。
- 经验可生成 Skill 候选，但不绕过 Skill 验证发布流程。

PostgreSQL：
- 支持显式外部连接配置、验证 TLS、CA、连接池、超时、迁移、备份和恢复；迁移权限与运行账号分离。
- 数据库连接不暴露给模型，不靠每个不可信 Worker 自填 tenant/role 获得权限；提供适合多节点的可信服务访问边界。
- 当前 PostgresStateStore 是项目级 JSON 状态读改写。核实与旧 PostgresMemory/SQL 是否形成两套数据模型；选定权威模型并提供迁移，不让两套数据静默分叉。
- 多节点实际路径要满足并发、细粒度授权、分页、增量和查询效率。不能仅整体读取一个巨大 JSONB，再在内存搜索，却宣称已经具有数据库全文/向量检索。
- PostgreSQL 保存正文、事实、来源、版本、回执、访问控制与可重建索引；大型附件可外置。实现参数化查询、并发版本检查、请求 ID 重放、事务 outbox。
- 搜索可用关键词基线，pgvector 为可配置增强，但增强模块未实现时必须明确未实现，而不是装饰性开关。向量模型/维度/版本绑定，迁移与降级明确。加入中文、代码符号与文件路径检索测试。
- 按条件提供关系/来源追溯查询；未授权的信息不能从摘要、计数、图边或证据入口泄露。
- 数据库不可用时，不自动生成第二份共享真相。本地待同步记录明确未提交；关键检查点未可靠落盘就暂停对应执行边界。
- 自动召回、自动采集、自动提炼和主动工具分别可控，并与项目/岗位设置形成清晰继承规则。

借鉴 OpenViking 的分层与 Pi 集成、gbrain 的持久化/回执、Hermes 的固定规则分离、Observational Memory 的来源链；不要同时启用多套自动采集器。引入源码或服务前重新读取锁定版本 LICENSE/依赖，不按过去的许可证结论直接复制。原理借鉴、直接依赖与代码复制在文档中分别列明。

- 现有 ProjectRunner 在 running.size 为 0 时退出：核查计划追加/外部事件是否能重新唤醒；不能仅支持第一批 Promise.race 补位。
- 现有 append 是程序方法：接入真正有预算和授权的滚动规划入口、低水位补充、任务调整、依赖环检查和计划版本冲突。
- 模块内部自主，公共接口版本化；开发依赖与交付依赖分开；共享文件/端口/数据库/测试环境有明确锁或隔离。
- 本地独立 worktree，远程独立检出；跨节点通过任务协议及产物传递，不共享可写工作目录。
- 全任务树、规划器、审核器和远程 Worker 统一容量与预算；等待父任务释放可复用名额，但不能免计所有子任务而无限扩张。
- 验证、审核、返工、集成均进入受控流程，审核积压时背压。不得只增加开发并发，最终仍由唯一主 Agent 手工处理全部交付。
- 检查命令来自可信配置，不由模型任意创建。用真实产物运行检查，而不是只比较 Agent 文本。
- 集成队列必须有单一有效执行权。现有 integrationTail 为进程内串行链：防止重复 /goal resume 或另一个协调进程同时向同一集成工作区合并。
- 集成/测试失败保留现场并提供修复路径，不能以“安全阻塞”为由永久锁死所有后续工作，也不能跳过失败强行继续。
- 任务和工作区身份包含 goal/run/attempt，避免下一目标复用 taskId 时与旧分支/路径碰撞。
- 取消、暂停与恢复的语义分别确定；运行中旧请求与远程迟到结果不能覆盖当前状态。节点故障时安全任务可从检查点恢复，未知副作用进入核对，不盲目重放。
- RemoteWorker 不仅有 HTTP 类，还要有可启动、可配置、受认证、具备心跳/租约和收敛关闭行为的部署入口。所有身份与能力由可信配置约束，不信任请求自报。
- worktree/文件钩子不等于 OS 沙箱。Shell 或测试命令开启时，按已选隔离后端限制凭据、网络、进程和宿主文件；暂未提供的保护必须标明。
- /goal 支持创建/状态/修改/暂停/恢复/取消或清除、预算、完成验收，并接入同一个项目队列，不叠加另一套无限 sendUserMessage 循环。
- 子任务提交只表示待验证；验收未过不能解锁强依赖或将记忆升级为已完成。
- 不靠大模型自报 done；按目标合同汇总自动检查、独立审核或用户接受。人工接受与自动质量证明在报告中区分。
- 可见状态解释为什么没有满并发：依赖、预算、资源、审核、权限、故障或没有合格工作，不只显示在线 Agent 数。

## 8. R7：搜索与网页读取

复用 Pi 本地 grep/find/ls/read；完善独立联网搜索后端与网页正文提取，保持与当前推理模型解耦。
Brave 适配已存在，优先把它的完整使用链、配置和测试做好。其他后端采用可替换接口，实际未完成的后端不虚报支持。

搜索/读取遵守岗位权限和数据出站规则；返回来源、访问时间、范围、缓存和截断标记。长内容以受控引用与分页处理。
网页抓取加入协议/主机约束、重定向检查、DNS/IP 与内网/元数据地址防护、有界响应和取消；不要把通用网页抓取变成任意内部网络访问器。对明确获准的内部 MCP 端点使用独立策略。
无配置、无密钥、后端失败时如实报告，不生成假搜索结果。线上命中不成为高优先级指令。

## 9. 自动化验证与最小端到端闭环

遵循 AGENTS 的安全测试方式，不运行可能因本机环境变量自动触发付费 API 的整个测试集合。

最低检查：
- 合格 Node 版本；使用 npm ci --ignore-scripts 安装锁定依赖。
- 依仓库要求生成/准备模型目录，记录生成版本/摘要；不手改生成文件冒充修复。
- 根 npm run check，保留完整日志；提交前确认它是否自动改了文件，仅保留属于当前工作的更改。
- 扩展独立 tsc 与 tsconfig.host.json 的真实 Pi 类型检查。
- extensions/pi861/test/*.test.mjs 的非付费确定性测试。
- pi-host.integration.mjs 与 runtime-host.integration.mjs 均真正运行而非 skip。
- 真实临时 PostgreSQL（非用户业务库）、受限账户、迁移升级、并发冲突、跨 scope 访问拒绝、撤回、断连及请求回执恢复测试。
- 真实子进程与本地 HTTP/SSE MCP fixture 测试，包括工具 schema 变化、失联和未知副作用。
- 两个实际 Worker 进程/容器的集成与故障测试；同机进程、同机容器、独立主机及真实模型服务分别标注，不能统称真实多服务器验证。
- Windows 路径/空格/终止行为与 Linux 行为的针对性覆盖；没有相应系统执行条件时写清未验证。

必须添加并通过的反例：
1. A 与慢任务 B 并行；A 验收后 C（依赖 A）在 B 结束前启动。空闲后追加任务仍能自动唤醒。
2. 提交产物未验收不解锁强依赖；审核失败产生可追踪返工，不伪造完成。
3. 备用/回切四组合；连续探测、探测预算、首选变更、用户取消、旧响应迟到。
4. 断流位于文字、工具参数中途、派发前/后、工具已成功但回执丢失；不重复副作用。
5. 实际安装两份通用 Debug 与一份专项 Skill 后进行整合、分支选择、更新及回滚；默认提示中不出现原始描述，更新不替换运行中版本。
6. 未激活 MCP 不全量暴露工具；激活后只出现必需项；撤权、跨账户、同名接口、重复 Skill 绑定、schema 变化与隐藏名直调均正确处理。
7. 记忆自动记录与提炼；换会话/换模型/换节点后恢复；私有信息不通过摘要和检索越权；撤回后旧任务与索引不能复活内容。
8. 记忆整理暂时失败后可有界恢复；数据库回执丢失用同一 requestId 确认结果；不以本地镜像冒充共享提交。
9. 重复 Goal 命令、进程重启、计划版本冲突、旧节点恢复，不产生双协调者/重复派工/重复集成。
10. 一个实际仓库样例，从 /goal 开始，经计划、真实 Pi Worker、Skill/MCP、记忆、验证和受控集成走通；模型使用 fixture 时明确标注，不宣称真实智能质量已验收。

再提供单独、默认关闭的真实模型/真实搜索/获准 MCP 验收脚本：明确凭据变量、预算上限、数据范围和清理步骤。没有授权就不运行，报告“代码与协议验证通过，真实服务验收待授权”，不能假装通过，也不能因此放弃其他模块。

## 10. 交付要求与工作停止条件

不要停在“写了计划”“创建了类”“内核测试通过”或“CI 修绿”。完成一个纵向流程后继续下一项就绪任务，直到本次能够完成的范围实际完成。
若因工具、权限或资源限制必须停止，保存可恢复状态、具体阻断条件和下一条操作；不能承诺自己会在对话结束后继续后台工作。

提交前：
- 仅 stage 自己的显式路径，不 git add . / -A，不绕过 hooks，不 force push。
- 依赖与锁文件作为代码审查，直接依赖固定版本，遵循仓库锁文件保护规则；不运行未批准的生命周期脚本。
- 每个提交关注一组可验证变化。不要为了规避规则先提交不合格代码再说以后修。
- 不自动 merge main，不发布正式版本。正式生产就绪声明必须有与实际部署范围匹配的证据。

最终给用户并写入 HANDOFF/验证文档：
1. 起始 SHA、最终分支和提交 SHA；工作区是否干净，是否存在未推送改动。
2. R1–R8 对应的行为、代码入口、测试用例、证据和状态；未完成项必须单列。
3. 最终用户真正应运行的启动命令及脱敏配置示例；升级、停机、恢复、回滚方法。
4. 每个检查的命令、运行环境、退出码、通过/失败/跳过数量、日志路径、CI run 链接；未跑和 skip 不计通过。
5. 真实/模拟、同机/跨主机、本地库/真实 PostgreSQL、协议/质量验收的清楚界限。
6. 关键故障注入报告、权限隔离结果、已知风险与复现步骤。
7. 第三方实际依赖或复制代码的版本、许可证、来源及修改记录。
8. 审核者从干净检出重现的最短步骤；日志不得包含凭据、私人数据或用户业务内容。

旧 VERIFICATION.md 保留为历史记录，新报告指向实际测试的提交。如果最后只补了文档，清楚列出被测试的代码 SHA 和之后的文档-only 差异，不把旧报告默认为最新全部代码已过关。

不要自动接受自己的交付。保留审查分支，由外部审核者复核实现、测试和需求覆盖后再决定合并。
